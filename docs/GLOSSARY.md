# Glossary / 术语表

Use these words, and only these, in code, docs, tests, commit messages and discussions. Most of the confusion in this project comes from the first two groups: you **follow** a **journal**, but you **save** an **article**.

在代码、文档、测试、提交说明及讨论中，统一使用下表的术语。最容易混用的是前两组：**关注**的是**期刊**，**收藏**的是**文章**。

## Things the user acts on / 用户的操作

| Term | 中文 | Meaning in this project | Where in the API |
|---|---|---|---|
| **follow** / **unfollow** | **关注** / **取消关注** | Put a **journal** on the bookshelf, or take it off. Only journals are followed. | `POST /bookshelf`, `DELETE /bookshelf/{journal_id}` |
| **bookshelf** | **书架** | The list of followed journals, in the order followed. There is one bookshelf, for the mock user. | `GET /bookshelf` |
| **save** / **remove** (a saved article) | **收藏** / **取消收藏** | Keep an **article**, or drop it. Only articles are saved. BrowZine calls this list "My Articles". | `POST /saved-articles`, `DELETE /saved-articles/{article_id}` |
| **saved articles** | **已收藏文章** | The list of saved articles, in the order saved. | `GET /saved-articles` |
| **mark read** | **标记已读** | Set one notification to read. It is permanent: there is no "mark unread". | `POST /notifications/{notification_id}/read` (no body) |
| **export a citation** | **导出引用** | Get a BibTeX or RIS record of a **saved** article, built only from stored metadata. | `GET /saved-articles/{article_id}/citation?format=bibtex\|ris` |

## Things in the data / 数据中的对象

| Term | 中文 | Meaning in this project | Where |
|---|---|---|---|
| **journal** | **期刊** | `J01`–`J10`, all in Artificial Intelligence; `subject` is an AI sub-area. | `GET /journals`, `GET /journals/{journal_id}` |
| **issue** | **期** | One issue of a journal, `I01`–`I20`; status `published` or `in_press`. | `issues` in journal details |
| **in press** | **待刊** | An issue with no publication date yet (`status: "in_press"`, `publication_date: null`). Its articles can be listed and saved, but it has **no notification**. | `status` of an issue |
| **article** | **文章** | `A001`–`A060`; belongs to one issue. | `GET /journals/{journal_id}/articles` |
| **notification** | **通知** | "A new issue was published": exactly one per **published** issue, ID `N-<issue_id>` (e.g. `N-I05`). Created from the seed, never by a clock or job. | `GET /notifications` |
| **visible** (notification) | **可见** | A notification is visible only while its journal is followed. Unfollowing hides it but keeps its read state; following again shows it as it was. A hidden notification is a `404` for mark read. | `GET /notifications` |
| **read** / **unread** | **已读** / **未读** | The state of one notification (not of an article). | `read` field |
| **unread count** | **未读数** | Unread visible notifications: per journal on each bookshelf entry (`unread_count`), and for all followed journals in `meta.unread_count`. | `GET /bookshelf`, `GET /notifications` |
| **mock user** `U1` | **模拟用户** | The one fixed user. A label only: there is no `user_id` parameter and no authentication. | — |
| **seed data** | **种子数据** | `data/mock_data.json`, generated by `scripts/generate_seed.py`. Loaded only into an empty database. | — |
| **reset** | **重置** | Replace all data with the seed (`reset --yes`). Deletes every change. | `./start.sh reset --yes` |

## API conventions / 接口约定

| Term | 中文 | Meaning | Where |
|---|---|---|---|
| **data / meta envelope** | **data/meta 响应格式** | Every JSON success is `{"data": ..., "meta": ...}`; `meta` only where it says something (paging, `unread_count`). | API_DESIGN.md, "Response format" |
| **problem details** | **错误详情（RFC 9457）** | Every 4xx body: `application/problem+json` with `type`, `title`, `status`, `detail`, `instance`; a `422` adds `errors`, one per invalid field (`pointer` or `parameter`). | API_DESIGN.md, "Response format" |
| **conflict** (`409`) | **冲突** | The action repeats or contradicts the current state (follow twice, export an unsaved article). Nothing changes. | API_DESIGN.md, "Shared rules" |
| **contract** | **接口契约** | `docs/API_DESIGN.md` plus `openapi.json`; `tests/test_contract.py` checks the service against them. | — |

## Running and deploying / 运行与部署

| Term | 中文 | Meaning | Where |
|---|---|---|---|
| **acceptance demo** | **验收演示** | `scripts/demo.py`: runs the user journey against a running service, then undoes its own follow and save. Repeatable; leaves the data unchanged. | HANDOVER.md §2 |

| **volume** | **持久卷** | `browzine-data`, mounted at `/data`; holds the database across restarts and redeploys. | HANDOVER.md §1 |

## Words to avoid / 避免使用的词

| Do not say | Say instead |
|---|---|
| subscribe, favourite, star, bookmark (a journal) | **follow** a journal / 关注期刊 |
| save, collect, add to favourites (a journal) | **follow** a journal |
| follow, bookmark, like (an article) | **save** an article / 收藏文章 |
| "收藏" for a journal | **关注** |
| alert, update, message (for a notification) | **notification** / 通知 |
| "delete" in prose, for a saved article or bookshelf entry | **remove** / **unfollow** (the article or journal itself is never deleted; `DELETE` is only the HTTP method) |

## Adding a term / 新增术语

When a genuinely new concept is needed, agree on what it means first (before writing code), then add its name and definition here, and only then use it in code and docs.

确有需要的新概念：先把含义说清楚，再把商定的名称和定义补进本表，然后才在代码和文档中使用。
